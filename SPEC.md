```json
{"node_id":"prepared-node-id","source_node_id":"n","type":"integer_output","status":"available","value":17}
```

The same native item receipt retains `session_id`, `graph_id`, batch/item identity; the job retains pinned connection/backend/queue scope and provenance. Exposure requires an exact known item ID, matching native scope/batch/graph, and source node ID in the submitted graph. Prepared IDs are mapped only through native `prepared_source_mapping`; no fuzzy matching. Intermediate scalar nodes are included deliberately; image finality rules are unchanged.

The snapshot copies only pinned primitive DTO `integer_output.value` (signed 64-bit integer, never a boolean) and `boolean_output.value` (strict boolean). Other DTOs, including strings, images, tensors and collections, get `unsupported_type` without copied contents. Invalid primitive values get `invalid_value`; oversized integers get `value_out_of_range`. A malformed/oversized type becomes null with `unsupported_type`. No arbitrary field flattening, string/path/blob copying, internal execution graph or session serialization is added to the receipt. Native remains the execution authority; this is an observation, not a compiler or a second native store.

At most 64 entries per item, with each prepared/source/type identifier limited to 256 UTF-8 bytes (oversized node IDs are omitted). Admission already bounds runs to four. `total`, `omitted`, `unscoped`, `truncated` and `max_entries` describe the snapshot; `unscoped` includes invalid/oversized/foreign IDs and `truncated` means the entry budget omitted otherwise scoped results. Retention follows native result iteration order, not a topological selection. Empty results mean no native results observed, not successful typed output. Unsupported or omitted output never changes native execution success into a fabricated value.

An observed terminal native-graph receipt with results is retained against stale or stripped later native observations. Missing native history marks `history_missing`, preserving already observed values, IDs, receipt, terminal state and provenance across restart/purge; results never observed before deletion cannot be reconstructed. Exact request replay does not enqueue. Reads of `generation.get` need no native query and work while native is stopped.
