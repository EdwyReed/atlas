# Canonical adoption activation contract

- Preserve the accepted capture receipt, source ledger, reservations and all unknown states. Upgrade is an explicit offline, checksum-bound transition from an accepted runtime receipt; never rewrite the original plan or receipt. Incomplete refresh blocks Engine construction.
- Operator evidence binds the current complete WAL-aware ledger, target, capture receipt, runtime, exact unresolved job rows and evidence-file hashes. A hold is not terminal evidence. Current remote backend/account generation is unproven: hold activation admits local CPU/corpus/media only; native effects, model-dependent admission, automatic observation, receipt maintenance and replay remain fenced. Explicit receipt/history reads remain available. New local work has normal idempotency, never reuses held intents.
- Match the installed old public anonymous attribution contract only through an explicit deployment setting; authenticated standalone remains the default. Reuse exact configured censor runtime/model. Mask requires a source-only private subordinate binding to the same accepted model/Python, not a second worker on the deployed socket/cache. Preserve the existing projection setting.
- Refresh takes both source and target existing ownership locks. An operator-reviewed preparation binds exact complete target ledger, owned file inventory, original runtime/dependencies and current successor runtime. The final fenced source cut uses SQLite backup (including committed WAL), all tables/schema, and changed file bytes only. No second full-root copy and no SQL field cherry-picking. Stage the small complete registry and changed files, fsync an incomplete marker before mutation, publish a completed refresh receipt only after exact source/destination verification. Interrupted refresh cannot start and resumes only against its recorded same source cut; source drift and target writes refuse.
- Production acceptance activity is explicitly bracketed: preserve a complete stopped-target registry baseline before calls, archive the complete resulting registry and only acceptance-added media files, then restore the entire baseline, never selected columns. Refuse any changed/deleted baseline-owned file. All acceptance histories remain in the private archive; no copied source history is removed. This bracket is for this fenced quarantine's local CPU/media acceptance, not a general rollback of user work.
- Final refresh invalidates activation evidence and returns to quarantine. The deployment owner prepares exact held evidence at that final cut and activates local admission and starts the successor only under the live fence.
- Adopted-root portable self-contained backup remains unsupported and must refuse; same-host rollback retains OLD and all original configuration. No remote mutations, GPU jobs, source deletion or ACL expansion are part of these changes.
